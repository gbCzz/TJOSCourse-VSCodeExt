# TJOS-VSCodeExt 开发执行计划 v1.1

日期：2026-09-27。依据原 PROJECT_PLAN.md、最新抓包复核、HTTP 观测合同与接口实现约定。本文件是后续执行基线；原计划保留架构背景。当前交付为接口与计划文档，尚未编写插件。

## 1. 交付目标与范围

首个可试用版完成：登录→选择本人可见实验仓库→下载到本地→编辑→差异/显式同步→构建环境终端→运行 QEMU→VNC。Windows 本机 VS Code 桌面扩展优先，API 同步模式；一个模块化扩展，无独立 CLI 或常驻服务，不增加平台权限。

首版不包含仓库重命名、未经验证的文件重命名、原生 Git 推送、自动作业提交、课程统计模拟、文件系统写入。参考图谱、完整原生调试、教学面板作为后续版本。只读原型先交付，避免同步/调试不确定项阻塞全部工作。

## 3. 第一轮开发任务（按顺序执行）

| ID | 工作 | 完成定义 |
|---|---|---|
| T01 | 检查仓库指令/状态，初始化扩展 manifest、tsconfig、构建和最小测试 | 可打包 VSIX 并在扩展宿主激活；扩展名称/发布者暂用开发值，正式发行前确定 |
| T02 | PlatformClient 和响应解码 | JSON、CSV、允许空正文分开；HTTP/业务错误归一；取消/超时有效；状态变更无盲目重试 |
| T03 | 脱敏 fixtures | 优先 login/me/401、repos/tree/file、save/delete、ensure、debug Busy；人工合成凭据与私有内容；类型/结构保留 |
| T04 | 认证与 SecretStorage | 本机真实登录、重启恢复、me 校验、退出；无日志泄漏；无 token 用途猜测 |
| T05 | 只读 Explorer 和下载 | 选择明确本地目录，拒绝覆盖未知文件，仓库路径严格验证，显示下载进度/取消 |
| T06 | 同步模型与预览 | B/L/R 纯逻辑测试覆盖冲突、远端删除、本地删除、中断未知；先预览后上传 |
| T07 | 受控联调与能力表 | 使用指定测试仓库验证写入/删除 SHA、容器同步、WS Origin/重连；能力从 observed 升级为 host-verified |

T01–T05 为首轮可演示目标。接口合同中的路径和字段用于实现，源码值和真实凭据不得复制入项目。

## 4. 验证缺口与处理时点

| 项目 | 何时完成 | 当前处理 |
|---|---|---|
| 独立客户端认证、过期/撤销 | P0 | me 成功样本已补齐，仍需扩展宿主验证；失败阻止私有接口启用 |

需要平台维护者回答的问题集中成一次清单：会话撤销/续期和客户端支持；文件条件写与大小/编码边界；容器同步/持久化；网关令牌/Origin；GDB 租约/查询副作用；课程记录规则。能用原型直接验证的项目不等待全套书面答复。

## 5. 代码组织与测试策略

建议模块：platform/auth、workspace/sync、sessions/terminal/build、analysis、debug、views、diagnostics。核心逻辑独立于 VS Code UI。远端工作目录、平台仓库和 UNIX 客户机磁盘严格区分。

测试聚焦风险：路径和隔离、三方同步、部分成功/结果未知、错误解码、串行调试与代际丢弃。协议契约以脱敏样本覆盖正常、空态、业务失败；集成测试在指定测试仓库运行；不使用真实作业做故障注入。开始写入联调前明确测试仓库身份。

性能在 P1/P3 建立固定数据和操作基线；P4/P6 再对照测量 P50/P95、请求数、传输量和增量内存。保留原计划目标作为待冻结工程指标，不用 HAR 时间直接宣称用户交互或扩展性能达标。

每次交付说明：启用能力、未验证/降级能力、验证方式、已知限制。P0/P1 可在后续阻塞存在时继续；P2/P3 遇到一致性或身份验证问题必须保留只读/手动降级。
